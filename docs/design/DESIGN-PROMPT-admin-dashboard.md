# นิยามหน้านี้

หน้าเปิดกะทำงานของแอดมิน ตอบ 2 คำถามตามลำดับนี้:
**“ตอนนี้มีอะไรค้างต้องทำ”** แล้วจึง **“ที่ผ่านมาขายได้เท่าไหร่”**

กติกาที่ใช้ตัดสินทุกองค์ประกอบ:
- ตัวเลขงานค้างทุกตัว **ต้องกดได้ และกดแล้วไปหน้าที่กรองไว้ให้แล้ว** — กดไม่ได้ = ของประดับ = ตัดออก
- ตัวเลขสรุปยอดขาย **ต้องบอกช่วงเวลาเสมอ** ห้ามมีตัวเลขลอยที่ไม่รู้ว่านับจากเมื่อไหร่

# บล็อกที่ต้องออกแบบ (4 บล็อก เรียงตามนี้)

## 1. หัวหน้า + ตัวเลือกช่วงเวลา

“ภาพรวมแอดมิน” + คำอธิบายสั้น 1 บรรทัด
ขวามือ: **pill filter ช่วงเวลา — วันนี้ · 7 วัน · 30 วัน** (ทรงเดียวกับแท็บในหน้าคิวงานจัดส่ง)
ตัวเลือกนี้คุมเฉพาะบล็อก 2 เท่านั้น **ไม่คุมงานค้าง** (งานค้างคือ ณ ปัจจุบันเสมอ) — ต้องออกแบบให้ขอบเขตนี้อ่านออก ไม่ให้เข้าใจผิดว่าคุมทั้งหน้า

## 2. สรุปยอดขาย

**3 ตัวเลข** ในการ์ดเดียวหรือ 3 การ์ดเรียงกัน (เลือกมาแบบเดียว):
- **ยอดขายรวม** (฿) — ตัวเด่นสุด สี `#6d28d9`
- **จำนวนคำสั่งซื้อ**
- **ยอดเฉลี่ยต่อออเดอร์**

แต่ละตัวมี **ตัวเลขเทียบช่วงก่อนหน้าที่ยาวเท่ากัน** (7 วันนี้ เทียบ 7 วันก่อนหน้า) เป็นข้อความสั้น เช่น “มากกว่า 7 วันก่อน 12%”
สีขึ้น `#16a34a` / ลง `#dc2626` **ใช้กับตัวเลขเทียบเท่านั้น อย่าให้สีลามไปทั้งการ์ด**

**กราฟ 1 อัน** ใต้ตัวเลข — ยอดขายรายวันของช่วงที่เลือก:
- แท่ง (หรือเส้น) ทึบสี `#6d28d9` · แกน/เส้นกริด `#f3f4f6` · ตัวอักษรแกน `12px #9ca3af`
- ช่วงก่อนหน้าซ้อนเป็นเงาจาง `#e5e7eb` ไม่ใช่สีที่สอง
- **ห้ามไล่เฉดใต้เส้น ห้ามเงา 3D ห้าม legend หลายสี**
- **ต้องออกแบบ state ข้อมูลบาง** — ข้อมูลจริงตอนนี้กระจุกเป็นวันเดียว กราฟที่มี 1–2 แท่งต้องยังดูตั้งใจ ไม่ใช่ดูพัง

⚠️ นิยามที่ต้องเขียนกำกับไว้บนหน้า: **“ยอดขาย” นับเฉพาะออเดอร์ `paid·shipped·shipping·delivered`**
ไม่นับ `pending·failed·cancelled·refunded` — ต้องมีที่ให้แอดมินอ่านนิยามนี้ (คำอธิบายใต้ตัวเลข หรือ tooltip)

## 3. งานค้างที่ต้องทำ

**การ์ดตัวเลข 4 ใบ เรียงตามความเร่ง กดได้ทุกใบ:**

| การ์ด | นับจาก | กดแล้วไป |
|---|---|---|
| **ต้องจัดส่ง** — ใบเด่นสุด | ออเดอร์ `paid` ที่ยังไม่มี `Shipment` เลย | คิวพัสดุ กรอง “รอสร้างพัสดุ” |
| **ค้างเกิน 2 วัน** | กลุ่มข้างบนที่ `createdAt` เกิน 2 วัน — ถ้า > 0 ใช้โทนเตือน `#c2410c`/`#fff7ed`/ขอบ`#fed7aa` | คิวพัสดุ เฉพาะที่ค้าง |
| **พัสดุติดขัด** | `Shipment.status` = `failed` หรือ `returned` | คิวพัสดุ กรองติดขัด |
| **รอชำระเงิน** | ออเดอร์ `pending` — ยังไม่ใช่งานของแอดมิน โทนเงียบที่สุดในกลุ่ม | `/admin/orders` กรอง `pending` |

**กติกา: 0 ต้องดูเหมือน 0** — ใบที่เป็นศูนย์ต้องจางลง ไม่ใช่โชว์เลข 0 ตัวโตเท่าใบที่มีงาน 12 ชิ้น
ต้องมีสถานะ **“เคลียร์หมดแล้ว”** ตอนทุกใบเป็น 0 (หน้าคิวงานจัดส่งใช้วงกลม `#dcfce7` + เครื่องหมายถูก `#16a34a` — ใช้ภาษาเดียวกัน)

**แถบสถานะพัสดุ** เล็กๆ ต่อท้าย: กำลังขนส่ง / ส่งสำเร็จ / ติดขัด เป็นสัดส่วนแถบเดียวหรือชิปเรียงกัน
**ห้ามทำเป็นโดนัทชาร์ตแยกอีกอัน** — หน้านี้มีกราฟได้อันเดียวคือกราฟยอดขาย

## 4. สินค้า

**สองตารางเคียงกัน** (desktop) / ซ้อนกัน (mobile) — ทรงตารางเดียวกับหน้าคิวงานจัดส่งเป๊ะ:

- **สต็อกใกล้หมด** — คอลัมน์: รูป+ชื่อสินค้า · หมวดหมู่ · จำนวนคงเหลือ · ปุ่มไป `/admin/products`
  `stock === 0` = “หมด” (โทน `#dc2626`/`#fef2f2`) · `1–5` = “ใกล้หมด” (โทน `#c2410c`/`#fff7ed`)
  โชว์ 5 แถวแรก + ลิงก์ “ดูทั้งหมด (N)”
- **สินค้าขายดี** — อันดับ 1–5: ลำดับ · รูป+ชื่อ · จำนวนที่ขายได้ · ยอดเงิน
  ตัวเลขอันดับใช้ตัวเลขธรรมดา ไม่ต้องมีถ้วยรางวัล/เหรียญ/อิโมจิ

## State ที่ขอ (ทุก state ใช้ภาษาเดียวกับหน้าคิวงานจัดส่ง)

- **ปกติ** — มีงานค้าง มีข้อมูลขาย
- **เคลียร์หมด** — งานค้างเป็น 0 ทุกใบ (ต้องรู้สึกว่า “จบแล้ว” ไม่ใช่ “พัง”)
- **loading** — skeleton ทรงเดียวกับของจริง (แถบ shimmer ในกรอบการ์ด/แถวตาราง) **ห้าม spinner กลางจอ**
- **error แยกส่วน** — ตัวเลขขายโหลดไม่ได้ แต่บล็อกงานค้างยังต้องใช้งานได้ (และกลับกัน)
  ใช้แบนเนอร์แดง `#fef2f2`/ขอบ`#fecaca` + ปุ่ม “ลองใหม่อีกครั้ง” เฉพาะในการ์ดที่พัง ไม่ใช่ทั้งหน้า
- **mobile 390** — ตารางเลื่อนแนวนอนในการ์ด (`overflow-x:auto`, ตาราง `min-width` ประมาณ 560px) ไม่ใช่บีบคอลัมน์จนอ่านไม่ออก

## ข้อมูลที่มีจริง (ห้ามใส่ฟิลด์ที่ไม่มีในนี้)

```
Order      orderNumber, status(9 ค่า), total, subtotal, shippingFee, totalQuantity, createdAt, updatedAt, user, address
OrderItem  product, price, quantity, lineTotal
Product    name, price, stock, imageUrl, storeType('mall'|'seller'), category, ratingAvg
Shipment   trackingNumber, status(7 ค่า: pending·picked_up·in_transit·out_for_delivery·delivered·failed·returned),
           lastLocation, estimatedDeliveryAt, createdAt, carrier
User       name, email, role, emailVerified
```

ทุกตัวเลขบนหน้านี้ **คำนวณฝั่ง frontend จาก endpoint ที่มีอยู่แล้ว** ไม่มี API สรุปยอดให้:

| ต้องการ | มาจาก |
|---|---|
| ยอดขาย / จำนวนออเดอร์ / กราฟรายวัน / รอชำระเงิน | `GET /orders` (ทุกออเดอร์ พร้อม `total` + `createdAt` + `status`) |
| ต้องจัดส่ง / ค้างเกิน 2 วัน / พัสดุติดขัด / สินค้าขายดี | `GET /orders/admin/shipping-queue` (คืน `paid·shipped·shipping·delivered` พร้อม `orderItems` + `shipments`) |
| สต็อกใกล้หมด | `GET /products` |

## สิ่งที่ตัดออกแล้ว — ห้ามออกแบบกลับเข้ามา

ทั้งหมดนี้พิจารณาแล้วว่า **ไม่มีข้อมูลรองรับ** ถ้าใส่มาคือตัวเลขปลอม:

- **ทราฟฟิกเว็บ / ผู้เข้าชม real-time / แหล่งที่มา (Facebook, Google, Direct)** — ไม่มี analytics ในระบบเลย
- **คูปอง/โปรโมชัน** — ไม่มีตารางคูปอง หน้า “เก็บโค้ด” ฝั่งลูกค้าเป็น mock
- **คำขอคืนเงิน/คืนสินค้า** — ไม่มี flow ไม่มีตารางคำขอ (`refunded` เป็นสถานะปลายทางที่ยังไม่มีใครเซ็ต)
- **“รอแพ็กของ”** — ไม่มีสถานะนี้ ระบบไปจาก `paid` → `shipped` ตอนสร้างพัสดุเลย
- **สินค้าค้างสต็อก/ขายไม่ออก (slow-moving)** — ไม่มี `lastSoldAt` ไม่มีข้อมูล view เหลือแค่ “หมดสต็อก” ที่ทำได้จริง
- **ลูกค้าใหม่ vs ซื้อซ้ำ / สมาชิกสมัครใหม่** — คำนวณได้แต่กดทำอะไรต่อไม่ได้ และ `GET /users` ยังไม่ส่ง `createdAt` ออกมา → ยกไปเฟสหน้า
- **activity feed “กิจกรรมล่าสุด”** — ไม่มี audit log ไม่มี event stream
- **ระบบร้านค้า/ผู้ขายรายราย** — `storeType` เป็นแค่ป้ายข้อมูล ไม่ใช่เจ้าของร้าน
- ไม่ต้องออกแบบ login/สิทธิ์ · **ไม่ต้องมีโหมดมืด**

## หมายเหตุถึงคนอิมพลีเมนต์ (ไม่ใช่โจทย์ดีไซน์)

- **ห้ามใช้ `Product.soldCount` ทำอันดับสินค้าขายดี** — คอลัมน์มีอยู่จริงแต่ค่าปลอม: seed สุ่ม 0–1000 ใส่ไว้,
  `products.service.ts` ตั้งเป็น 0 ตอนสร้าง และ **ไม่มีที่ไหนบวกเพิ่มตอนขายจริง** ให้รวมจาก `OrderItem` แทน
- `GET /orders` (`findAll`) โหลด relation แค่ `user`, `address` — **ไม่มี `orderItems`/`shipments`**
  ของสองอย่างนั้นต้องเอาจาก `shipping-queue` เท่านั้น
- `Order.total` / `OrderItem.lineTotal` เป็น `decimal` → `pg` คืนมาเป็น **string** ต้อง `Number()` ก่อนบวก
- ยิง 3 endpoint ขนานกันและให้พังแยกกันได้ — ตารางสินค้าพังไม่ควรทำให้การ์ดงานค้างหายไปด้วย
- `GET /products` ยังเปิดโล่งไม่มี auth ต้องใส่ `@UseGuards(AuthGuard, RolesGuard) @Roles('admin')` ก่อนใช้จริงในหน้าแอดมิน
- ถ้าออเดอร์โตถึงหลักพันแถว การดึงทั้งตารางมาคำนวณฝั่ง client จะเริ่มช้า — ตอนนั้นค่อยเพิ่ม `GET /orders/admin/stats` ดีไซน์ไม่ต้องรอ
