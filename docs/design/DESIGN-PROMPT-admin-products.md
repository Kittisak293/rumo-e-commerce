# นิยามหน้านี้ (อ่านก่อนออกแบบ)

แคตตาล็อกสินค้าทั้งร้าน — เพิ่ม แก้ไข และลบสินค้า

**งานที่แอดมินทำบ่อยที่สุดในหน้านี้ไม่ใช่ “เพิ่มสินค้าใหม่” แต่คือ “ไล่ดูว่าอะไรใกล้หมดแล้วแก้สต็อก/ราคา”**
ดีไซน์ต้องทำให้ **กวาดสายตาหาของที่ผิดปกติเจอเร็ว** และ **เข้าไปแก้ได้ในไม่กี่คลิก** —
ปุ่ม “เพิ่มสินค้า” มีที่ทางชัดเจนได้ แต่ไม่ควรครองหน้า

หน้านี้ยังเป็น **ปลายทางของการ์ด “สต็อกใกล้หมด” บนหน้าภาพรวมแอดมิน** — กดจากตรงนั้นแล้วต้องมาถึงหน้านี้
ในสภาพที่ **กรองเหลือเฉพาะสินค้าใกล้หมดไว้ให้แล้ว** ต้องออกแบบให้รองรับสถานะ “เข้ามาพร้อมตัวกรองติดมา”

# โครงหน้าที่ต้องออกแบบ

## 1. หัวหน้า

“จัดการสินค้า” + sub สั้นๆ · ตัวนับ “ทั้งหมด 156 รายการ” เป็นข้อความเรียบ **ไม่ใช่การ์ด KPI**
ขวาสุด: **ปุ่มหลัก “+ เพิ่มสินค้า”**

## 2. แถบเครื่องมือ

- ช่องค้นหา — ค้นด้วย **ชื่อสินค้า**
- **ตัวเลือกหมวดหมู่** — dropdown (หมวดหมู่มีได้หลายสิบ ทำเป็น pill ไม่ไหว)
- **pill ประเภทร้าน** — ทั้งหมด · Mall · Seller
- **pill “สต็อกใกล้หมด”** — ตัวกรองด่วนอันเดียวที่ต้องกดถึงได้ในคลิกเดียว (ปลายทางจากหน้าภาพรวม)

ต้องเห็นตลอดว่าตอนนี้กรองอะไรอยู่ และ **ล้างตัวกรองทั้งหมดได้ในคลิกเดียว**

## 3. ตาราง

| คอลัมน์ | รายละเอียด |
|---|---|
| สินค้า | รูป `44px; radius:10px; object-fit:cover` + ชื่อ `13.5px #1d1d1d` (ยาวเกิน 2 บรรทัดให้ตัด `…`) |
| หมวดหมู่ | ข้อความ `#6b7280` |
| ประเภท | chip `mall` `#6d28d9`/`#ede9fe` · `seller` `#6b7280`/`#f3f4f6` — **เป็นแค่ป้ายกำกับ ไม่ใช่เจ้าของร้าน** |
| ราคา | `600 #6d28d9` **จำนวนเต็มบาท ไม่มีทศนิยม** (คอลัมน์ในฐานข้อมูลเป็น `int`) |
| สต็อก | ปกติ = ตัวเลขธรรมดา · `1–5` = chip เตือน `#c2410c`/`#fff7ed`/ขอบ`#fed7aa` · `0` = chip “หมด” `#dc2626`/`#fef2f2`/ขอบ`#fecaca` |
| — | ปุ่ม “แก้ไข” (ปุ่มรอง) + ปุ่ม “ลบ” (ปุ่มอันตราย) ชิดขวา |

**สต็อกใกล้หมด/หมด ต้องอ่านออกทันทีตอนกวาดสายตา** โดยไม่ต้องเพ่งอ่านตัวเลข —
แต่ **ห้ามย้อมทั้งแถวเป็นสีแดง/ส้ม** ตารางจะอ่านไม่ออก ให้จำกัดสีไว้ที่ chip สต็อกเท่านั้น

⚠️ **ห้ามทำ inline edit ในตาราง** (กดตัวเลขสต็อกแล้วพิมพ์ทับตรงนั้น) — API ไม่รองรับการแก้ทีละฟิลด์
(เหตุผลอยู่ในหมายเหตุถึงคนอิมพลีเมนต์ท้ายไฟล์) การแก้ทุกอย่างต้องผ่านฟอร์มเต็ม

## 4. ฟอร์มเพิ่ม / แก้ไข — **dialog**

ใช้ dialog ให้เข้าชุดกับ dialog ที่โปรเจกต์มีอยู่แล้ว (`CreateShipmentDialog`, `AddShipmentEventDialog`)
กว้างประมาณ 560px · การ์ดขาว radius 18 · หัว dialog + ปุ่มปิด · ปุ่ม “ยกเลิก / บันทึก” ล่างขวา

ฟิลด์ (เท่านี้ ห้ามเพิ่มฟิลด์ที่ระบบไม่มี):

| ฟิลด์ | ชนิด |
|---|---|
| ชื่อสินค้า | text |
| รายละเอียด | textarea (ระบบเก็บเป็นข้อความยาว ไม่มี rich text ไม่มี markdown) |
| ราคา | ตัวเลข **จำนวนเต็ม** มีสัญลักษณ์ ฿ นำหน้า |
| จำนวนในคลัง | ตัวเลขจำนวนเต็ม |
| หมวดหมู่ | select — **บังคับเลือก** |
| ประเภทร้าน | segmented 2 ตัว: Mall / Seller — **บังคับเลือก** |
| รูปสินค้า | **รูปเดียว** — drop zone + พรีวิว + ปุ่มเปลี่ยนรูป |

**ทั้งฟอร์มเพิ่มและฟอร์มแก้ไขใช้ฟิลด์ชุดเดียวกันครบทุกช่อง** — ฟอร์มแก้ไขต้อง prefill ค่าเดิมมาให้ครบ
**ห้ามออกแบบฟอร์มย่อแบบ “แก้เฉพาะสต็อก” หรือ “แก้เฉพาะราคา”** (API ไม่รองรับ ดูหมายเหตุท้ายไฟล์)

ต้องออกแบบ:
- **ช่องรูป** — ทั้งตอนยังไม่มีรูป (drop zone ว่าง), ตอนมีพรีวิวแล้ว, และตอน **กำลังอัปโหลด**
- **ข้อผิดพลาดรายฟิลด์** — เช่นไม่ได้เลือกหมวดหมู่ / ราคาติดลบ (ข้อความแดงใต้ช่อง ไม่ใช่ alert รวมด้านบน)
- **สถานะกำลังบันทึก** — ปุ่มบันทึก disabled + สปินเนอร์ในปุ่ม ห้ามให้กดซ้ำได้

## 5. ยืนยันลบ

dialog เล็ก · ไอคอนเตือนแดง · **ระบุชื่อสินค้าที่จะลบให้ชัด** · ปุ่มยืนยันเป็นแดงทึบ ปุ่มยกเลิกเป็นปุ่มกลาง
ถ้อยคำต้องตรงกับพฤติกรรมจริง: **สินค้าจะหายจากหน้าร้านทันที และหน้านี้ไม่มีทางกู้คืนกลับมา**

## 6. ของที่ต้องกันไว้เป็นเฟสถัดไป (ออกแบบเป็น variation แยก อย่ายัดรวมฟอร์มหลัก)

- **แกลเลอรีหลายรูปต่อสินค้า** — ระบบมีตาราง `ProductImage` แยกต่างหาก แต่รูปที่โชว์ในร้านคือ `Product.imageUrl` เพียงรูปเดียว
  และ `ProductImage` มีแค่ฟิลด์ลำดับ (`index`) **ไม่มีธง “รูปหลัก”** — ถ้าจะออกแบบ ให้บอกชัดว่าเป็นงานเฟสถัดไป
- **ตัวเลือกสินค้า / SKU (สี ไซซ์)** — โครงสร้างในฐานข้อมูลมีแล้ว แต่ยังไม่มี API ให้จัดการ **อย่ายัดเข้าฟอร์มหลักเด็ดขาด**

## State ที่ขอ

- **มีข้อมูล** (desktop 1280) — ต้องมีทั้งแถวปกติ แถวใกล้หมด และแถวหมดสต็อกในภาพเดียว
- **เข้ามาพร้อมตัวกรอง “สต็อกใกล้หมด”** (มาจากหน้าภาพรวมแอดมิน)
- **ค้นหาไม่เจอ** — ต่างจาก “ยังไม่มีสินค้าในระบบ” และต้องมีปุ่มล้างตัวกรอง
- **ยังไม่มีสินค้าเลย** — empty ที่พาไปเพิ่มสินค้าชิ้นแรก
- **loading** — skeleton ทรงแถวตาราง **ห้าม spinner กลางจอ**
- **error** — แบนเนอร์แดง + ปุ่มลองใหม่
- **dialog เพิ่มสินค้า** (ว่าง) · **dialog แก้ไข** (มีค่าเดิม + มีรูปเดิม) · **กำลังอัปโหลดรูป** · **ผิดพลาดรายฟิลด์**
- **dialog ยืนยันลบ**
- **mobile 390** — ตารางเลื่อนแนวนอน + dialog กลายเป็นเต็มจอ

## ข้อมูลที่มีจริง (ห้ามใส่ฟิลด์ที่ไม่มีในนี้)

```
Product    name, description, price(int), stock(int), imageUrl, storeType('mall'|'seller'), category
Category   name, slug, imageUrl
```

**ไม่มีฟิลด์พวกนี้ในระบบ อย่าออกแบบช่องกรอกให้:**
SKU/รหัสสินค้า · บาร์โค้ด · น้ำหนัก/ขนาดพัสดุ · ราคาทุน · ราคาโปรโมชัน/ส่วนลด · แท็ก ·
สถานะเผยแพร่ (เปิด/ปิดการขาย) · วันที่เริ่มขาย · ผู้ขาย/ร้านค้า

## สิ่งที่ยังไม่มีในระบบ — ห้ามออกแบบ

- **ห้ามแสดงคะแนนรีวิวหรือยอดขายในตาราง** — `ratingAvg` `ratingCount` `soldCount` มีคอลัมน์อยู่จริง
  แต่เป็นค่าที่ seed สุ่มใส่ไว้ ไม่มีระบบรีวิวและไม่มีอะไรบวกยอดขายตอนสินค้าถูกซื้อ → เอามาโชว์ = ตัวเลขปลอม
- **ไม่มีสถานะเปิด/ปิดการขาย** — ลบคือ soft delete ล้วน ไม่มีการ “ซ่อนชั่วคราว”
- **ไม่มีการแก้ไขหลายรายการพร้อมกัน (bulk edit)** ไม่มี checkbox เลือกหลายแถว
- **ไม่มีการนำเข้า/ส่งออกไฟล์ CSV/Excel**
- **ไม่มีประวัติการแก้ไข (audit log)** — ห้ามมี “ใครแก้ราคาเมื่อไหร่”
- **ไม่มีการแบ่งหน้าฝั่ง server** — ถ้าจะออกแบบ pagination ต้องเป็นแบบทำฝั่ง client
- **ไม่มีระบบร้านค้า/ผู้ขายรายราย** — `storeType` เป็นแค่ป้ายข้อมูล ไม่ใช่เจ้าของ
- ไม่ต้องออกแบบ login/สิทธิ์ · **ไม่ต้องมีโหมดมืด**

## หมายเหตุถึงคนอิมพลีเมนต์ (ไม่ใช่โจทย์ดีไซน์)

หน้านี้มีกับดักฝั่ง API เยอะที่สุดในบรรดาหน้าแอดมิน — ทั้งหมดนี้ต้องแก้ก่อนหน้าจะทำงานได้จริง:

- **`PATCH /products/:id` ต้องส่งข้อมูลครบทุกฟิลด์เสมอ** — `ProductsService.update` เรียก
  `categoriesRepository.findOneByOrFail({ id: dto.categoryId })` ทุกครั้งโดยไม่เช็ค undefined
  → ยิง PATCH ที่ไม่มี `categoryId` มาด้วย = พังทันที **นี่คือเหตุผลที่ห้าม inline edit และห้ามฟอร์มย่อ**
- **ชื่อฟิลด์ไฟล์ต้องเป็น `imageUrl`** — controller ใช้ `FileInterceptor('imageUrl')`
  แต่ `productStore` ปัจจุบัน `formData.append('file', file)` → **ไฟล์ถูกทิ้งเงียบๆ สินค้าได้รูป `unknown.jpg`** ต้องแก้
- **`productStore` ไม่ส่ง `storeType`** แต่ `CreateProductDto` บังคับ (`@IsEnum`) และ `main.ts` เปิด
  `ValidationPipe({ whitelist: true })` ไว้ → `POST /products` จาก store ตอนนี้ **400 แน่นอน** ต้องเพิ่มฟิลด์
- **`/products` ทั้ง controller ไม่มี auth เลยสักชั้น** — ใครก็ยิง `POST`/`PATCH`/`DELETE` ได้
  **ต้องใส่ `@UseGuards(AuthGuard, RolesGuard) @Roles('admin')` ที่ route เขียนข้อมูลก่อนปล่อยหน้านี้ขึ้นจริง**
  (`GET` เปิดไว้ได้ หน้าร้านฝั่งลูกค้าใช้อยู่)
- `Product.price` เป็น `int` — ราคาทศนิยมใส่ไม่ได้ ถ้าอนาคตต้องการต้องเปลี่ยนเป็น `decimal` พร้อม transformer
- `DELETE /products/:id` เป็น **soft delete** (`deletedAt`) — ข้อมูลยังอยู่ในฐานข้อมูล แต่ไม่มี UI กู้คืน
- `GET /products` โหลด relation `category` มาให้แล้ว ใช้กรองหมวดหมู่ฝั่ง client ได้เลย
- router guard เช็ค `meta.requiresAdmin` — หน้านี้ได้มาจาก parent route `/admin` อยู่แล้ว
