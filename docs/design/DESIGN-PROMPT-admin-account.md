# Design prompt — RUMO หน้า Account + Admin shell

> ก๊อปทั้งไฟล์นี้ไปวางใน Claude Design ได้เลย
> (ต่อยอดจาก `DESIGN-PROMPT-shipping-admin.md` — ใช้ภาษาภาพชุดเดียวกัน ไม่ต้องคิดธีมใหม่)

---

ออกแบบ **หน้า “บัญชีของฉัน” (`/account`)** ของ RUMO (e-commerce หลายผู้ขาย, ภาษาไทย, desktop-first)
หน้านี้คือ **ทางเข้าเดียว** ของทั้งลูกค้าและแอดมิน — กดไอคอนโปรไฟล์บน header แล้ว **ไปหน้านี้ตรงๆ**
(ของเดิมเป็น dropdown `q-menu` เล็กๆ ที่มีแค่ชื่อ + ลิงก์ admin + ออกจากระบบ → เลิกใช้)

**สิ่งที่ต้องออกแบบมี 3 ชั้น:**
1. หน้า `/account` เวอร์ชันลูกค้า
2. หน้า `/account` เวอร์ชันแอดมิน (ศูนย์รวมเครื่องมือหลังบ้าน)
3. **drawer ซ้ายที่สลับโหมด** — พอเข้าโหมดแอดมิน เมนูซ้ายเปลี่ยนเป็นชุดแอดมินทั้งชุด

## 1. Drawer โหมดแอดมิน (ชิ้นที่สำคัญที่สุดของงานนี้)

พอผู้ใช้ที่ `role === 'admin'` เข้าหน้า `/account` หรือหน้าใดๆ ใต้ `/admin/*`
**drawer ซ้ายเปลี่ยนทั้งชุด** เป็นเมนูแอดมิน โดยยังใช้ทรงการ์ดขาว/active ม่วงเดิม

**ลำดับเมนูตัดสินแล้ว ห้ามเรียงใหม่** — เรียงตามความถี่การใช้งานจริง (ใช้ทุกวันอยู่บน / ตั้งค่าครั้งเดียวอยู่ล่าง)
แบ่ง 3 กลุ่มด้วยเส้นคั่น `#d1d5db` + หัวข้อกลุ่มตัวเล็ก (`12px/600` สี `#6b7280`, ไม่ใช่การ์ด)

```
┌ โหมดผู้ดูแลระบบ ────────┐
│  ภาพรวมแอดมิน           │
├─ งานประจำวัน ───────────┤
│  พัสดุ                  │
│  คำสั่งซื้อ              │
├─ แคตตาล็อก ────────────┤
│  สินค้า                 │
│  หมวดหมู่               │
├─ ตั้งค่าระบบ ───────────┤
│  บริษัทขนส่ง             │
│  ผู้ใช้                 │
└────────────────────────┘
   ← กลับหน้าร้าน           (ปักล่างสุด แยกจากทุกกลุ่ม)
```

| เมนู | ปลายทาง | เปิดไปเจออะไร | API |
|---|---|---|---|
| ภาพรวมแอดมิน | `/account` | ตัวเลขงานค้าง กดแล้วเด้งเข้าคิวที่กรองไว้แล้ว | ประกอบจาก shipping-queue |
| **พัสดุ** | `/admin/shipments` | คิวงานประจำวัน — สร้างพัสดุ / บันทึกเหตุการณ์ | ✅ มีหน้าจริงแล้ว |
| คำสั่งซื้อ | `/admin/orders` | ทะเบียนออเดอร์ทั้งหมดไว้ค้นหา **ดูอย่างเดียว** | ✅ `GET /orders` |
| สินค้า | `/admin/products` | ตารางสินค้า เพิ่ม/แก้ราคา/แก้สต็อก/อัปโหลดรูป | ✅ CRUD ครบ |
| หมวดหมู่ | `/admin/categories` | รายการหมวด เพิ่ม/แก้ชื่อ/เปลี่ยนรูป/ลบ | ✅ CRUD ครบ |
| บริษัทขนส่ง | `/admin/carriers` | ทะเบียนขนส่งที่เลือกได้ตอนสร้างพัสดุ + ลิงก์ติดตาม | ✅ มีหน้าจริงแล้ว |
| ผู้ใช้ | `/admin/users` | รายชื่อคนสมัคร + ตั้ง role | ✅ CRUD ครบ |

**หมายเหตุการตั้งชื่อ:** โหมดแอดมินตัดคำว่า “จัดการ” ออกทุกเมนู เพราะ drawer กว้างแค่ 220px และตัวอักษร 20px —
“จัดการบริษัทขนส่ง” จะตกบรรทัด ส่วนหัวข้อกลุ่มบอกบริบทอยู่แล้ว

**สังเกต:** เมนูที่ “ลงมือทำงาน” ได้จริงมีแค่ **พัสดุ** อันเดียว ที่เหลือคือดูข้อมูลกับตั้งค่า —
น้ำหนักภาพต้องสะท้อนแบบนั้น อย่าทำให้ทั้ง 7 อันดูสำคัญเท่ากัน

**โจทย์ออกแบบที่ต้องตอบให้ชัด: “จะรู้ได้ยังไงว่าตอนนี้อยู่โหมดไหน และจะกลับไปฝั่งลูกค้ายังไง”**
การสลับเมนูทั้งชุดโดยไม่มีสัญญาณ = ผู้ใช้หลง ขอ **2–3 ทางเลือก** พร้อมบอกว่าอันไหนดีกว่าเพราะอะไร เช่น
- แถบหัว drawer “โหมดผู้ดูแลระบบ” + ปุ่ม “← กลับหน้าร้าน” ปักล่าง
- ปุ่มกลับหน้าร้านลอยอยู่บนสุดแทน
- สลับด้วย toggle ค้างไว้บนสุดของ drawer

**ไม่ต้องมีปุ่มออกจากระบบใน drawer** — อยู่ในหน้า `/account` แล้ว ใส่ซ้ำจะแย่งที่กับ “กลับหน้าร้าน” ซึ่งใช้บ่อยกว่ามาก

ต้องมี: **desktop 1280 · mobile 390 (drawer ปิด → เข้าถึงยังไง)** · สถานะ active ของแต่ละเมนู
เช็คด้วยว่า 7 เมนู + 3 หัวข้อกลุ่ม (~500px) ยังพอดีจอ desktop โดยไม่ต้อง scroll drawer

## 2. หน้า `/account` — เวอร์ชันลูกค้า

การ์ดบนสุด: avatar (ไม่มีรูปจริงในระบบ — ใช้ตัวอักษรย่อในวงกลม) · ชื่อ · อีเมล · badge “ยืนยันอีเมลแล้ว/ยังไม่ยืนยัน”

ด้านล่างเป็นเมนูการ์ด:
- คำสั่งซื้อของฉัน → `/orders` (โชว์ตัวเลขออเดอร์ที่ “กำลังจัดส่ง” ได้ถ้ามีที่ดึง)
- ที่อยู่จัดส่ง → จัดการที่อยู่
- การแจ้งเตือน → `/notifications`
- ออกจากระบบ (สีแดง `#dc2626`, แยกออกจากกลุ่มอื่น)

**ขอ state:** ปกติ · mobile 390 · ยังไม่ยืนยันอีเมล (ต้องมี CTA ให้ยืนยัน)

## 3. หน้า `/account` — เวอร์ชันแอดมิน (ภาพรวม)

หน้านี้คือ **หน้าเปิดกะทำงาน** ไม่ใช่หน้ารายงานผู้บริหาร คนเปิดมาเพื่อรู้ว่า “วันนี้ต้องทำอะไรบ้าง แล้วกดเข้าไปทำ”

โครงที่ขอ:

1. **แถบตัวตน** — ชื่อ + อีเมล + badge “ผู้ดูแลระบบ” (ม่วง `#6d28d9`/`#ede9fe`)
2. **การ์ดงานค้าง 3–4 ใบ เรียงตามความเร่ง** — ตัวเลขต้องเป็นงาน ไม่ใช่ยอดขาย:
   - `ต้องจัดส่ง` (ออเดอร์ `paid` ที่ยังไม่มีพัสดุ) — **การ์ดเด่นสุด**
   - `กำลังจัดส่ง` (`shipped` + `shipping`)
   - `ค้างเกิน 2 วัน` (SLA จริงของตลาด) — ถ้ามีมากกว่า 0 ต้องอ่านออกทันทีว่าผิดปกติ
   - `รอชำระเงิน` (`pending`)
   แต่ละใบกดแล้วเข้าคิวงานที่กรองไว้แล้ว ไม่ใช่แค่ตัวเลขโชว์เฉยๆ
3. **ทางลัดเครื่องมือ** — การ์ด/กริดของเมนูแอดมินทั้ง 6 (ตามตารางข้อ 1) พร้อมคำอธิบาย 1 บรรทัดต่อใบ
4. **ออกจากระบบ**

**ขอ state:** มีงานค้าง · **ไม่มีงานค้างเลย (empty ที่รู้สึกดี ไม่ใช่รู้สึกว่าพัง)** · loading (skeleton ทรงเดียวกับการ์ด ไม่ใช่ spinner กลางจอ) · error · mobile 390

**ขอ variation:** การ์ดตัวเลขเรียงแถวบนสุด vs รวมเป็นแถบเดียวแล้วดันทางลัดเครื่องมือขึ้นมาเด่นแทน — อันไหนทำให้ “เริ่มทำงาน” เร็วกว่า

## 4. หน้าแอดมินย่อยที่ยังไม่มีดีไซน์ (ขอโครงคร่าวๆ พอให้ต่อยอดได้ ไม่ต้องละเอียดเท่าข้อ 3)

หน้าจัดการพัสดุ / บริษัทขนส่ง **มีดีไซน์และโค้ดแล้ว ไม่ต้องทำซ้ำ** เหลืออีก 4 หน้า:

- **จัดการคำสั่งซื้อ** — ตารางออเดอร์ทั้งหมด + ตัวกรองสถานะ 9 ค่า + ค้นหาเลขออเดอร์/อีเมลลูกค้า → กดดูรายละเอียด
  ⚠️ **ห้ามมีปุ่มแก้ `Order.status` ตรงๆ** — สถานะขยับเองจากการชำระเงินและการบันทึกเหตุการณ์พัสดุเท่านั้น
- **จัดการสินค้า** — ตาราง (รูป · ชื่อ · หมวดหมู่ · `storeType` mall/seller · ราคา · สต็อก) + ฟอร์มเพิ่ม/แก้ไข + อัปโหลดรูป (หลายรูปต่อสินค้า, มีรูปหลัก)
  หมายเหตุ: สินค้า 1 ตัวมีหลาย SKU จากตัวเลือก (สี/ไซซ์) — ถ้าออกแบบตัวจัดการ SKU ให้ทำเป็น **variation แยก** ระบุว่าเป็นงานเฟสถัดไป
- **จัดการหมวดหมู่** — รายการ + รูปหมวดหมู่ + เพิ่ม/แก้ไข/ลบ (ต้องเตือนก่อนลบหมวดที่มีสินค้าอยู่)
- **จัดการผู้ใช้** — ตาราง (ชื่อ · อีเมล · role · ยืนยันอีเมลแล้วหรือยัง · วันที่สมัคร) + เปลี่ยน role
  ⚠️ ต้องมีกันพลาด: แอดมินปลดสิทธิ์ตัวเองไม่ได้

## สิ่งที่ยังไม่มีในระบบ — อย่าออกแบบ

- **ไม่มีข้อมูลยอดขาย/กราฟ/รายงาน** — ไม่มี endpoint สรุปยอด อย่าใส่กราฟรายได้ ยอดขายรายวัน หรือ KPI การเงิน
- **ไม่มีระบบคูปอง** (หน้า “เก็บโค้ด” ฝั่งลูกค้าเป็น mock) — ไม่ต้องมีเมนูจัดการคูปอง
- **ไม่มีระบบร้านค้า/ผู้ขายรายราย** — `storeType` เป็นแค่ป้ายข้อมูล ไม่ใช่เจ้าของ ไม่ต้องมีเมนู “จัดการร้านค้า”
- **ไม่มีระบบคืนเงิน/คืนสินค้า** — `refunded` เป็นสถานะที่ไปถึงได้ แต่ไม่มี flow ให้กด
- **ไม่มีรีวิว/แชท/ระบบส่งการแจ้งเตือนหาลูกค้า** — ตาราง `Notification` มีอยู่แต่ยังไม่มีอะไรเขียนลงไป
- ไม่ต้องออกแบบ login/สิทธิ์ (มี `role: admin` + guard อยู่แล้ว)
- ไม่ต้องมีโหมดมืด

## หมายเหตุถึงคนอิมพลีเมนต์ (ไม่ใช่โจทย์ดีไซน์)

- `GET /users`, `POST/PATCH/DELETE /products`, `/category` **ยังไม่มี `RolesGuard`** (`/users` มีแค่ `AuthGuard`, products/categories เปิดโล่ง)
  ถ้าจะทำหน้าจัดการผู้ใช้/สินค้า/หมวดหมู่จริง **ต้องใส่ `@UseGuards(AuthGuard, RolesGuard) @Roles('admin')` ก่อน**
- ตัวเลข “ค้างเกิน 2 วัน” / “ต้องจัดส่ง” คำนวณจาก `GET /orders/admin/shipping-queue` ที่มีอยู่แล้ว ไม่ต้องเพิ่ม endpoint
- router guard ปัจจุบันเช็ค `meta.requiresAdmin` — เมนู/หน้าใหม่ทุกหน้าต้องติด meta นี้ด้วย
